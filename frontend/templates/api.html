The API

Scanning from a script

The form is one of two front doors; the other is JSON, and it is the same handler.

Submit & poll

Submit and poll

curl -X POST https://scan.okxo.de/api/scans \
     -H 'Content-Type: application/json' \
     -d '{"target_url": "opencloud.example.com", "release_track": "production"}'
curl https://scan.okxo.de/api/scans/<uuid>

A submission answers 202 with the scan's identifier; polling it returns queued, running or the finished result, and 404 once it has expired. Only four fields are read - the address, the checks to waive, the release track and the output format. Anything else in the body, concurrency and timeouts above all, is rejected: how hard this server probes is not a caller's decision.

The schema

The schema

The machine-readable documents are always public, on this deployment and on every other: the OpenAPI 3.1 description of every operation, and the Arazzo 1.0.1 workflows that say how those operations combine into submitting a scan, waiting for it and taking the result away. {% if docs_enabled %} Both are browsable here as Swagger UI and ReDoc, served from this server like everything else - nothing is fetched from anywhere. {% else %} The interactive viewers (Swagger UI at /docs, ReDoc at /redoc) are switched off on this deployment; an operator turns them on with COS_WEB_ENABLE_DOCS=true. {% endif %}
