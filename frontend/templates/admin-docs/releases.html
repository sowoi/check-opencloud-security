[1.33.2] - this release

Changed

  • The advisory database knows GHSA-p6cc-4vh9-2hjq. OpenCloud published it as "DDoS Attac Vector through Crash in Search Service": an authenticated user can crash the search service with a crafted search query. When OpenCloud runs as a single binary, that takes down the whole instance. It is rated medium and fixed in 4.0.9, 7.2.5 and 9.1.0, so the scanner reports it for releases before 4.0.9, from 4.1.0 up to (but not including) 7.2.5, and from 7.3.0 up to (but not including) 9.1.0.
  • The release schedule knows 9.1.0, 7.2.5 and 4.0.9. OpenCloud published all three on 2026-11-11, but the lifecycle page does not list them yet, so the generator could not pick them up. They were added by hand: 9.1.0 opens the new rolling line 9.1, 7.2.5 is the current production release and 4.0.9 the current LTS release. An instance still on 9.0.0, 7.2.4 or 4.0.8 is now reported as behind its track.
  • A release no longer rolls back release-schedule entries the lifecycle page does not list yet. The release workflow now runs scripts/update_release_schedule.py --never-older: when the page names an older current release for a track than the checked-in schedule, the file is kept. Without the flag, as in the weekly refresh, the page still wins.

Fixed

  • A backport named only in an advisory's patched list is no longer reported as vulnerable. OpenCloud wrote GHSA-p6cc-4vh9-2hjq as < 9.1.0 and listed 7.2.5 and 4.0.9 only under patched versions. The repository advisory parser read those only when there was no range at all, so it would have reported the patched 7.2.5 and 4.0.9 as affected. A patched version below the upper bound now splits the range at its line, the same way < 4.0.8, < 7.2.0 already did.
  • The daily advisory refresh no longer fails on a real advisory. The refresh tests made up advisories for versions such as 9.0.1 and assumed no real advisory covered them. GHSA-p6cc-4vh9-2hjq did, so the refresh workflow failed before it could open its pull request. The tests now use versions far beyond any real release, and a new test fails with a clear message if a bundled advisory ever covers one of them.
  • The suite no longer grades the fake OpenCloud by this week's advisories. The fake reports 7.2.3, which GHSA-p6cc-4vh9-2hjq covers, so about thirty tests about ratings, output formats and policies failed once the advisory was bundled. The plugin and scanner runs in those tests now leave the bundled database out (COS_SCANNER_BUNDLED_DB=false, or include_bundled_db=False), and the tests about advisories turn it on explicitly. The web report and browser tests run a release no advisory covers and fail with a clear message if one ever does.

[1.33.0] - 2026-11-10

Changed

  • The bundled stacks run Valkey instead of Redis. Every compose file, the stack docker/setup-wizard.py generates and the CI test service now use valkey/valkey:9.1-alpine in place of redis:8.10-alpine, start valkey-server and check their health with valkey-cli through VALKEYCLI_AUTH. Valkey is the BSD-licensed continuation of Redis and speaks the same protocol, so the service name redis, COS_WEB_REDIS_URL, COS_REDIS_PASSWORD and the Python client are unchanged and an existing .env keeps working. Upgrade note: a stack generated with persistence (volume or filesystem) must empty its data directory or volume once before the first start, because Valkey refuses a data file written by Redis 8. The default stacks persist nothing. See ADR 0081 and docs/redis.md.
  • The CI tools are current again. On its first run, scripts/check_tool_pins.py found six pins behind their latest release. All six are raised wherever they are written (workflows, CLAUDE.md, AGENTS.md, CONTRIBUTING.md, the preflight skill):
  • ruff 0.17.1 → 0.17.4
  • zizmor 1.30.1 → 1.32.0
  • Biome 2.5.13 → 2.6.6, including the schema in biome.jsonc
  • mermaid-cli 12.0.0 → 12.2.0

  • uv 0.13.1 → 0.13.7, as required-version and in the docker/ images alike
  • its second weekly run (#174) found ruff and Biome a patch behind again, and both were raised once more

The new ruff, zizmor and Biome find nothing in the repository. nfpm 2.48.0 replaces its RPM writer, so the .rpm built on the pull request is installed on Fedora before a release relies on it. A local uv older than 0.13.7 now refuses to run here. - The signed-in stack runs authentik 2026.8.5. The key now carries the runner image, as the system package cache's already did.

Documentation

A # v4 that upstream had moved therefore passed locally and failed only in CI. The preflight skill, CLAUDE.md and AGENTS.md now pass GH_TOKEN="$(gh auth token)". Without a signed-in gh, preflight reports a warning that the online audits did not run.
  • CLAUDE.md says Firefox does not start inside Claude Code's sandbox. It fails with Could not find profile folder, which looked like a broken browser build. Outside the sandbox the Firefox browser tests pass.

[1.32.2] - 2026-11-05

Changed

  • A failed browser test leaves a Playwright trace. In CI a Firefox run once timed out loading /api, a page the same run had just loaded cleanly, and the log could not say which request hung. With PLAYWRIGHT_TRACE_DIR set, the page fixture in tests/browser_support.py records each test and keeps the trace only when the test fails. browser-tests.yml sets it and uploads the traces as playwright-traces-<browser> for seven days. Open one with uv run playwright show-trace. Locally nothing is recorded unless the variable is set; with it, the browser suite took 66 s instead of 64 s.
  • A version bump is the whole release pull request. Releasing 1.32.1 took three extra commits and two red CI runs. Three changes remove that (ADR 0080):
  • An advisory record for an entry under ## [Unreleased] now says changelog_version: unreleased (and fixed: unreleased) instead of guessing a number. scripts/release_notes.py writes the version in when it renames the heading, the release commit carries the records, and the release dry run checks them. Before, the record had to name the version in pyproject.toml, which is the release already out until the bump, so every security entry broke the check on the bump.
  • scripts/check_pull_request.py refuses a version change that does not bring the regenerated Releases page and search indexes with it, and names the commands. A bot commit that regenerated them afterwards would run no checks. The edit hook's prompt for a version change names them too.
  • A pull request that changes only the version (the version lines in pyproject.toml and uv.lock, and those regenerated files) counts as a release and needs no changelog entry of its own.
  • The browser tests cache the Playwright browser build. One 1.32.1 run hung downloading WebKit until the job timed out. The download is now cached, keyed on the locked Playwright version, and the install step has its own 10-minute limit. The system libraries are still installed through apt on every run.
  • A test takes the release through every step on a copy of the repository. tests/test_release_flow.py copies the tracked files, adds an [Unreleased] security entry with its unreleased record, and bumps the version. It runs the real generators and check_pull_request.py, then does what publish-pypi.yml does: release_notes.py, both generators again, the advisory check and the --check modes. It also fails if the release rewrites a file that the workflow's release commit does not stage. Each script already had its own tests; this one catches the steps drifting apart.
  • Bandit is pinned, and /preflight scans what CI scans. The workflow runs bandit@1.9.4 with bandit-sarif-formatter==1.1.1 instead of whatever is newest. The preflight skill used --recursive . on the working tree, which also took in .nox/ and mutants/ (about 3.3 million lines and hundreds of findings in third-party code). It now passes the tracked Python files, which is what CI's checkout holds.
  • CI runs a pinned uv. Every job logged "Could not determine uv version … Falling back to latest", so a new uv release could change what uv sync --locked does without a commit in this repository. pyproject.toml now sets required-version = ">=0.13.1" under [tool.uv], and every setup-uv step takes the lowest match, so CI installs exactly 0.13.1, the uv the Docker images copy in. It is a floor and not an exact pin, so a newer local uv still runs. Nothing raises it automatically; a test fails if a setup-uv step floats or a Docker image falls below it.
  • A weekly report names the CI tool pins that fell behind. Dependabot updates actions, locked packages and Docker images. It does not update the uvx/npx versions (ruff, zizmor, Bandit, Biome), the binaries downloaded against a SHA-256 (shellcheck, hadolint, actionlint, nfpm), mermaid-cli or uv's required-version. On its first run six of them were behind. scripts/check_tool_pins.py finds them in the workflows and compares each with its latest release, and tool-pins.yml keeps one issue open while any is behind. It only reports: a new binary needs its SHA-256 checked by hand. A new *_VERSION variable without a known release source fails the script, so a pin added later is watched from the start.
  • CI runs the test suite in slices. The coverage run took 19 minutes and each nox interpreter 15, almost all of it pytest on a single runner. pytest --shard INDEX/COUNT (tests/sharding.py) runs one slice. A test's slice is a stable SHA-256 of its node id, because the slowest test takes 7 of 507 seconds and no weights file would stay current. The coverage run is now four jobs (python 1/4 to python 4/4). A python job combines their data and applies fail_under to the whole suite, after checking that the slices ran every test exactly once. nox runs three slices per interpreter. A failing slice reproduces locally with the same --shard. The generated-file checks moved into their own generated files job.

Fixed

  • A browser test no longer fails because it moved on while a font was loading. A web font is fetched when text first needs it, which can be after the load event. When a test reloaded in that moment, Firefox aborted the download and logged downloadable font: download failed … status=2152398850 (NS_BINDING_ABORTED) as a console error, and the page watch failed the test. The first CI trace showed this for test_garbage_in_storage_is_ignored. The watch now ignores exactly that status. A font that fails for any other reason is still an error, and tests/test_browser_support.py checks both cases.
  • The browser tests cache their system packages too. Today the runners' Ubuntu mirror served packages at a few hundred kB/s, and playwright install-deps timed out for WebKit (114 MB) and Firefox (49 MB) on almost every run; only Chromium (21 MB) got through. The downloaded .deb files are now cached per browser, Playwright version and runner image, and saved right after the install, so a failing test does not discard them. apt checks each cached package against the fresh index and downloads only what changed. The install has 20 minutes, enough to fill the cache once over a slow mirror, and the job limit rose from 20 to 35 minutes.
  • The CI tool downloads retry a passing server error. A 504 from GitHub's release downloads failed the hadolint install on main. The same single attempt fetched shellcheck, actionlint and nfpm, and nfpm is installed inside the release in publish-pypi.yml. Every curl download now retries up to five times (--retry 5 --retry-delay 5), and the digest check after it still decides what is installed. tests/test_workflow_hardening.py now refuses a download without --retry, and a pin comment that names only a major tag.
  • The test suite no longer leaks HTTP error answers. In tests/test_service.py, each HTTPError a test caught kept its response open until the garbage collector closed it. That close came after the socket was gone and sometimes ended a full run with two PytestUnraisableExceptionWarnings (ValueError: I/O operation on closed file), reported in whatever test happened to be running. A helper now reads the status and body and closes the answer. The fake OpenCloud also stops printing a traceback when the scanner deliberately hangs up at its response cap, and the webhook test in tests/test_output_formats.py closes its listening socket.
  • Every pinned action names its exact release. Several actions were pinned to a commit hash but commented only with the major tag (actions/checkout # v7, actions/attest-build-provenance # v4, actions/attest # v4, docker/login-action # v4). zizmor, running online in the workflow lint, compares that comment with where the tag points now. When docker/login-action v4.8.0 moved v4, every pull request failed on a file it never touched. The comments now name the tag each hash is (v7.0.1, v4.2.2, v4.2.2, v4.7.0); the hashes are unchanged.
  • A failed advisory or release-schedule refresh no longer leaks its connection. When the OSV feed, the GitHub advisory API or the lifecycle page answered with an HTTP error status, the fetch wrapped the HTTPError in its own error and never closed the response it holds. Each failed daily refresh in the web service kept a socket open until the garbage collector reached it. opencloud_local_scan/fetch.py now opens all three through one helper, open_document, which closes an error answer before passing it on. Its status and reason stay readable.
  • A deliberate hook refusal no longer also says the hook "could not run". The wrappers in .claude/settings.json printed that message on every exit that was not 0, including the deliberate exit 2, so a decision read like a broken hook. Only an unexpected exit code prints it now; both still refuse.
  • The release-notes preview in AGENTS.md and CONTRIBUTING.md reverts with git restore. The branch guard read the documented git checkout CHANGELOG.md RELEASE.md as a switch to a branch called CHANGELOG.md and refused it.

Documentation

  • The documented test suite runtime is accurate. CLAUDE.md, .github/copilot-instructions.md and the preflight skill and agent said about 75 seconds. The suite takes about 8 minutes locally and about 15 minutes per Python version in CI.

[1.31.2] - 2026-09-25

Security

  • The erasure credential throttle counts an IPv6 client by its /64. Failed guesses at the DELETE /api/purge token were counted per single address, while every other limit counts an IPv6 client by the /64 it is handed - so rotating the interface identifier bought five fresh guesses each time. The 32-character minimum on the token kept guessing impractical regardless.
  • The scan service refuses a guessable token on a wide bind. Serving anywhere but loopback required a token but accepted any non-empty one - --token a, or the placeholder secrets/scanner_token.example ships with - and nothing counts failed attempts, so a short token let anybody who reached the port make it scan whatever they named. Such a bind now needs a token of at least 32 characters that is not that placeholder, or it refuses to start. openssl rand -hex 32, which every guide already uses, is unaffected.

Fixed

  • A check only one of two scans made is no longer called new or resolved. Comparisons read a finding missing from the earlier scan as passing, so a check added by a newer scanner - or by turning the extra checks on - was reported as a regression of the instance, and a check the later scan no longer made as fixed. The baseline, check-opencloud-scanner diff, the web comparison and compare_scans now list these as newly measured or no longer measured, based on each scan's coverage block, and the explanation files them as scanner changes. A newly measured failure still alerts, and --warn-on-new still does not suppress it. A report or baseline that does not list its checks is compared as before. See ADR 0079.
  • Aligned the report expiry footer, warning and live countdown to round remaining minutes up consistently in every language.
  • A comparison page rounds its expiry up too. It rounded the minutes left down, so it announced one minute fewer than the result page would.

Documentation

  • Added German, Spanish and French operator architecture and operations documentation, including localized document navigation and operator search. Section anchors and commands remain aligned with English; ADRs and release-note bodies remain English.

  • Clarified grouped remediation, upgrade estimates, report expiry and operator messages in English, German, Spanish and French. A simulated upgrade whose grade is limited by findings no longer implies that the grade cannot improve. Count labels also read correctly for a single finding.

  • Expanded all-language tests for remediation groups, upgrade estimates, escaped version strings, singular and plural expiry warnings, and the translated decision-record interface around English source documents.
  • Decision records are never translated. ADR 0077 records that every record in adr/ exists in English only, and once: the operator area shows it untranslated in every locale, and translation work leaves adr/ alone.
  • Changelogs and release notes are never translated. ADR 0078 records that CHANGELOG.md, RELEASE.md and the GitHub release body exist in English only, and that the operator area's Releases tab shows them untranslated in every locale.

[1.31.1] - 2026-09-24

Changed

  • The coverage warning's alert line is now covered by mutation testing. tests/test_coverage_regression.py drives _apply_baseline in process but was missing from the mutmut selection, so eleven mutants of the branch that lifts an OK to WARNING when a measured check turns inconclusive survived. It is now listed, and its test asserts the whole alert line: three of those mutants left OK: inside the WARNING message without a test noticing.

Fixed

  • The web report no longer offers "What gets you to A+" under an A+. When no step in the remediation plan raises the grade, because the instance already has the top grade or something no setting can change holds it down, the plan is headed "Still worth fixing, the grade stays A+" (or whichever grade it holds) instead. This applies to the dashboard, its contents list, and the PDF and HTML exports, in all four languages.
  • check-opencloud-scanner fleet lists waiver deadlines in the order they end. Deadlines were sorted by their text, so a waiver written with a +02:00 offset could be listed after one that ends later in UTC.
  • The fleet summary's "Not covered" count counts each host once. A host whose last scan failed long enough ago to be stale was counted twice.
  • The remediation plan no longer fails on a result document whose ratingExplanation.base is null. The update step's detail is then left empty, instead of remediation_plan() raising.

Security

  • An empty listen address no longer counts as loopback for the scan service. Binding "" listens on every interface, but the check that demands a token for anything but loopback let it through. The command line, COS_SERVICE_LISTEN and the configuration file all fall back to 127.0.0.1 when empty, so only a program calling build_server() or serve() with listen="" could reach it.
  • The container images install the dependencies uv.lock pins, with their hashes. Both docker/Dockerfile and docker/Dockerfile.web resolved their dependencies from PyPI at build time, so an image could ship versions that CI, pip-audit and the SBOM never saw.

[1.31.0] - 2026-09-24

Documentation

  • Polished scan progress, errors, downloads and sharing text in English, German, Spanish and French. Corrected informal Spanish instructions and clarified that saved downloads remain available after a scan expires.
  • Updated all four web-service guides to describe every export format, including offline HTML reports and remediation bundles. Expanded tests for translated error pages, email drafts, link-free summaries and download links.
  • Translation checks now catch additional Spanish forms of informal address and report broken guide links at their original line numbers, ignoring links shown only in code examples. Added regression tests for both cases.

Added

  • Coverage regression alerts. With --baseline, a check that an earlier run reached a conclusion on and that is inconclusive now raises an OK to WARNING, even when the grade has not moved. The rating, its perfdata and the findings are untouched: the scan saw less, the instance did not change. The warning lasts until the check is measured again, --warn-on-new does not suppress it, the webhook's baseline_diff carries the lost checks as coverage_regressed, and the two-document comparison reports a coverageRegressed scanner change. See ADR 0074 and Reporting only what changed.
  • Grouped remediation plans. remediationPlan.groups places every open finding in the system its fix is made in - the reverse proxy, the identity provider, OpenCloud or the DNS zone - and merges the findings one edit resolves into a single change: every missing header is one header block, every exposed path one proxy rule, and the update closes every matching advisory. Each change carries the rating it alone would give, replayed through the rating function, and groupSummary names the changes that resolve several findings at once. Shown by --debug, on the web dashboard ("What to change where"), in the remediation bundle, and returned by the plan_remediation MCP tool. See ADR 0075 and What would raise the rating.
  • Architecture decisions in the operator area. A new Decisions tab at /admin/decisions lists every architecture decision record with its status, and a filter narrows the list by number, title or status. Each record opens as its own page in English, and links between records, or from the Architecture tab, stay inside the area. The area's search now indexes every record's full text. Like the rest of the area, the records are never public: a stranger gets a 404, and they are absent from the public search, the sitemap and /documentation.
  • check-opencloud-scanner review-waivers. It reads the configured waivers (ignore_hardenings and temporary_waivers, or the --ignore-hardening and --waive-until values given to it) and lists five kinds that need attention. Expired waivers no longer suppress anything. Expiring soon ones run out within the waiver_warning window. Unused ones match no failing check in a --result document, or with no document, no identifier the scanner knows. Overlapping ones are already covered by another waiver, such as a deadline hidden under a permanent *. Permanent ones have no reason and no deadline. Each item has a suggested cleanup, for a permanent waiver a --waive-until record to copy. The command never changes the configuration. It exits 1 when it lists anything, unless given --exit-zero, and --format json suits scripts. See the scanner command.
  • check-opencloud-scanner fleet. It turns saved scan result documents into one summary of a fleet. Give it files, or directories that it searches for *.json, and it keeps the newest report of each host. It lists end-of-life releases and releases whose support ends soon. The recorded version is placed in today's release schedule again, so a line that closed after the report was written is listed too. It lists waivers that let a failing check alert again within --window days (default 30), measured against today. It counts the failing findings that most hosts share, and leaves out the ones no operator can change. Under missing coverage it lists stale reports (--stale-after, default 7 days), failed scans, checks the scans could not evaluate, and hosts named by --expect or --inventory that have no report. The output is text, Markdown, JSON, or one self-contained HTML page that fetches nothing. It never scans, stores nothing and applies no threshold, so it exits 0 whenever it printed a summary.
